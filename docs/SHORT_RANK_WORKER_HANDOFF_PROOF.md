# Original SHORT-rank worker-to-worker source continuity

The first-seen rank source in [#1156](https://github.com/Dtwosam/Cocomelon/pull/1156) is append-only *in one local paper-state directory*. It is not acceptable to trust a newly sealed GitHub rank archive in isolation if an exact successor silently reset or rewrote a losing rank observation from its predecessor. A deleted file could change which SHORT breakout trades the candidate claims to avoid.

`prospective_short_rank_worker_handoff.py` adds an explicit cross-worker source proof.

1. Before creating **either** separate paper account, verify **both** original completed-worker GitHub artifact ZIPs using the complete artifact-bound hash and rank-row verifier from #1160. Independently fetch both run JSON records through the authenticated GitHub API.
2. Demand a genuine later `workflow_dispatch` successor in the **same original repository**, matching `id`, `run_attempt`, `head_sha`, workflow path and main branch. The real GitHub Actions run API does **not** expose dispatch `inputs`; instead, the original paper-worker's **post-exit sealed rank artifact now carries both restored predecessor run ID and attempt from its immutable workflow dispatch context**. Require those sealed values to match the predecessor's independently bound run and attempt, and separately require GitHub's genuine `display_title` to name the same predecessor run. If the API ever includes `inputs`, those must match too. The predecessor must have completed.
3. Older sealed-worker sources lacking restored-predecessor metadata are still individually verifiable but **cannot** pass this stricter handoff proof; no historical event or dispatch metadata is backfilled. Demand that **every predecessor snapshot**, including features, ordinal ranking, decimal scores, empty-market snapshots and received/captured times, exists **unchanged at the same index** at the start of the successor's full archive. Recompute the prefix digest independently and require it to equal the predecessor's whole sealed rank-state digest.
4. Demand at least one truly new complete rank observation, with original chronology not regressing. Refuse reset, omission, selective loser deletion, rewritten rows, duplicate old snapshots, same-size-only handoffs, time regression, wrong predecessor identity or rerun attempts. The only legal continuation is an exact immutable prefix followed by later new observations.
5. Only on success may the separate `run_handoff_verified_original_rank_paired_replay` use the complete successor rank archive for **both** independent baseline and candidate paper accounts against the same separately pinned original market recorder archive and normal simulated fills, fees, funding, stops and account reconciliation.

**This is evidence continuity, not trade promotion.** A directly passed JSON object cannot prove it came from the GitHub API; the caller must fetch it authentically as in #1161. Passing this check also does not certify exchange provenance, feature-to-market linkage, all data gaps, terminal exposure maturity, capital/risk matching or after-cost profit. All economic readiness, full-account trial, promotion and live-order permissions remain FALSE. The frozen negative v5 result, ongoing original paper worker and original risk controls are unchanged.
